# Forkloom (`agentd`) 产品定位、核心能力与行业应用白皮书

> **一句话定义**：`Forkloom` 是一套运行在 Linux 内核之上的**有状态安全沙箱与整机运行态分叉引擎（Stateful Sandbox & VM Forking Runtime）**——用最直观的话说，它是面向 AI 时代的**“带存档/读档、快速平行宇宙克隆与防泄密网关的超级 Docker 底座”**。

---

## 一、技术层级与本质定位：它到底算不算“操作系统”？

在技术架构上保持绝对诚实，不玩概念文字游戏：

### 1.1 计算机系统栈中的精确坐标
1. **它 100% 构建在 Linux 宿主机内核之上**，不重复造物理网卡驱动、NVMe 磁盘驱动或底层内存页表管理。
2. 在严格的计算机科学分类中，它**不是裸机操作系统内核（Bare-metal Kernel）**，而是与 **`Docker (containerd)`、`VMware ESXi/vMotion`** 处于同一生态位的**虚拟化与系统运行时底座（System Runtime / Hypervisor Layer）**。
3. 在产品与商业叙事中称之为“面向 Agent 的新型操作系统层”，是因为对于运行在其上的 AI Agent 而言，`Forkloom` 接管了它的**计算隔离、内存冻结恢复、磁盘时空分支与网络出入口权限**（正如 Android 与 Kubernetes 均基于 Linux 内核，但向上定义了全新的计算范式）。同时，在微虚拟机模式下，沙箱内部（Guest OS）运行的极简 Linux 内核本身由 `Forkloom` 深度裁剪与定制。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 第 4 层：AI 与企业应用层                                            │
│   ├─ RL 训练框架 / SWE-bench 评测 / AI 编程平台 / CI 测试流水线 / 运维平台 │
├────────────────────────────────────────────────────────────────────┤
│ 第 3 层：Forkloom (agentd) —— 本项目所处核心层                       │
│   ├─ 核心职责：微虚拟机生命周期、内存+磁盘同步快照克隆、CoW 分叉、凭证网关   │
│   └─ 生态位对标：Docker Engine (containerd)、VMware vMotion          │
├────────────────────────────────────────────────────────────────────┤
│ 第 2 层：Linux 宿主机内核 (Ring 0)                                   │
│   └─ 底层原语：KVM 硬件虚拟化、cgroups v2、Namespaces、Btrfs/XFS CoW  │
├────────────────────────────────────────────────────────────────────┤
│ 第 1 层：物理硬件层                                                  │
│   └─ CPU 硬件虚拟化 (VT-x / AMD-V)、物理内存、NVMe SSD、网卡           │
└────────────────────────────────────────────────────────────────────┘
```

### 1.2 为什么不脱离 Linux 从零用 Rust 写裸机 OS？
- **避开商业死胡同**：从零编写裸机内核（如 Redox OS）需耗费数年解决硬件驱动与 POSIX 系统调用长尾兼容问题；只要缺失 1% 的 Linux 系统调用，用户的 `PyTorch`、`Node.js`、`PostgreSQL` 就会直接崩溃，无法商业化落地。
- **兼具生态兼容与深水区壁垒**：站在 `Linux + KVM` 之上，既能 **100% 零修改运行全球所有现成 Linux 软件与 Docker 镜像**，又能将全部研发精力集中在真正产生商业溢价的硬核深水区——**虚拟化内存快照预取、写时复制（CoW）存储引擎、崩溃一致性事务协议与零信任安全网关**。

## 二、核心价值辨析：它仅仅是一个“安全沙箱”吗？

**“安全沙箱”只是它的外壳（准入门槛），“可分叉、可倒流的状态时间机器”才是它的真正护城河。**

| 对比维度 | 传统容器 / 普通安全沙箱（Docker / gVisor / 普通云沙箱） | `Forkloom (agentd)` 有状态分叉运行时 |
| :--- | :--- | :--- |
| **设计隐喻** | **一次性防爆玻璃房**（关进去跑完即扔） | **带时间轴与克隆能力的防爆实验室**（像 `Git` 一样管理运行中的整台电脑） |
| **状态复制成本** | 拷贝含 20GB 数据库与依赖的环境需数分钟，服务冷启动需数十秒 | **冷分叉**（Btrfs 子卷快照）为 $O(1)$ 元数据操作；**热分叉**（连同已预热内存与运行中进程一起克隆）共享宿主页缓存快速唤醒 |
| **容错与回滚** | 跑崩环境或污染数据库后，只能销毁重建、重新导入数据 | 任意节点 `checkpoint()` 存档，破坏后直接 `restore()` 闪回干净现场 |
| **长周期等待** | 挂起等人工审批时要么常驻空烧算力，要么关停丢失内存上下文 | 支持整机状态冻结落盘释放算力与内存，事件到达后从持久帧唤醒继续执行 |
| **密钥安全性** | 多将 API Key 放入环境变量，易被 Prompt 注入攻击外带窃取 | **真密钥永不进沙箱**，由宿主机独立网关进程按路由策略在外部透明注入并防反射泄漏 |

**商业逻辑闭环**：
- 没有**硬件级沙箱隔离 + 零信任网关**，企业安全部门**不敢**让 AI 上生产（决定能不能入场）；
- 没有**带内存与数据库的快速分叉与状态闪回**，客户直接用免费 Docker 即可，**不必**为你付费（决定凭什么高溢价胜出）。

## 三、交付给用户的五大核心能力

去掉一切概念包装后，用户通过 `aos` CLI、Python / TypeScript SDK 或 MCP 接口直接获得的 5 项原子能力：

1. **零门槛吞吐标准 Docker / OCI 镜像与本地仓库（`import_oci` / `import_tar`）**
   直接导入企业现有的业务镜像、带数据的测试库镜像或开源评测基准镜像（如 SWE-bench），固化为不可变的初始世界母版（`Base Frame`），无需用户改造现有构建流程。
2. **“平行宇宙”并发克隆（`fork`：支持冷分叉与整机热分叉）**
   - **磁盘级冷分叉**：基于底层 Btrfs 子卷写时复制快速派生数十个独立环境；10GB 数据库在某个分支里被修改了若干数据块，磁盘仅新增增量块开销。
   - **整机运行态热分叉（VM 模式）**：将耗时数十秒启动完毕的测试框架、数据库连接池、语言运行时停在“待命瞬间”拍下内存+磁盘联合快照，快速裂变出 $N$ 台已预热就绪的独立微虚拟机并发试跑不同方案（底层自动处理内核随机数重播种、时钟校准与独立网络命名空间隔离）。
3. **任意时间点存档与状态闪回（`checkpoint` / `restore` / `hibernate`）**
   无惧 `rm -rf /`、依赖冲突或破坏性 SQL 迁移，一键闪回至任意已提交历史帧；支持长任务持久帧落盘休眠与按需唤醒。
4. **硬件级防逃逸隔离与“凭证不出宿主机”网关（`Capability Gateway`）**
   基于 KVM 微虚拟机提供独立内核级强隔离（防容器逃逸与 Fork 炸弹）；严格管控出网白名单，通过 `vsock` 显式网关转发与受控代填机制确保真实 API Key / 云凭证永不暴露在沙箱内存中。
5. **结构化变更提取与全链路加密审计（`diff` / `export_patch` / `audit`）**
   并发探索结束后，一键将胜出分支的文件变更经宿主路径安全校验后导出为标准 Git Patch 补丁，快速回收其余失败分支；完整留存命令轨迹、资源消耗与分段加密 I/O 审计日志，支持回归测试按序录制回放。

## 四、六大核心行业应用场景

### 场景 1：大模型强化学习“练兵场”与评测底座（RLVR / SWE-Gym）【首发破局场景】
- **目标客群**：大模型厂商、垂类 Coding / Computer-Use 模型研发团队、AI 评测机构与高校实验室。
- **落地价值**：在单台大内存裸金属 Linux 服务器上支撑高密度并发分叉（MCTS 树搜索采样）与快速重置，大幅减少 GPU 等待 CPU 环境重置的空转开销。

### 场景 2：企业研发的“无限全栈测试与预发环境”（干掉 Staging 环境排队）
- **目标客群**：中大型软件企业、SaaS 厂商、金融科技研发与 QA 团队。
- **落地价值**：将微服务与脱敏数据库打成预热母版。每个 PR、每次集成压测独享一套完整克隆环境（含已启动的本地数据库），测完即焚，彻底消灭测试环境排队与脏数据踩踏。

### 场景 3：AI 编程平台的“多路赛马式自主研发”（Best-of-N Coding）
- **目标客群**：大厂内部研发效能平台、云端 AI 软件工程 Agent 平台。
- **落地价值**：针对棘手 Bug 或重构任务直接调用 `fork()` 开出多个平行沙箱并发尝试不同方案、跑基准测试，自动择优提取安全校验后的 Git Patch。

### 场景 4：企业“数字员工”的云端专用安全电脑（受控办公与业务 Agent）
- **目标客群**：金融、财务、电商、大型政企内部落地自主业务 Agent 的团队。
- **落地价值**：提供“长周期落盘休眠唤醒 + 高危步骤前自动存档可撤回 + 真密钥不出宿主机网关”的专属防爆运行舱。

### 场景 5：生产高危运维变更的“数字孪生预演舱”（Autonomous SRE 保险栓）
- **目标客群**：银行、运营商、车企云平台、核心交易系统的运维与 DBA 团队。
- **落地价值**：高危 SQL 迁移或排障命令执行前，基于最新脱敏状态帧拉起影子沙箱完成真实预演（Dry-run），验证无误后再放行生产。

### 场景 6：网络安全动态引爆沙箱与快照级漏洞挖掘（Malware Sandbox & Snapshot Fuzzing）
- **目标客群**：网络安全公司、终端防护厂商、软件供应链安全团队、漏洞研究实验室。
- **落地价值**：将可疑第三方依赖包或畸形测试输入送入预热微虚拟机引爆观察，抓取文件与网络企图证据后快速从干净快照恢复，支撑高吞吐动态检测与 Snapshot Fuzzing。
